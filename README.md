# Платформа для проведения онлайн-конференций

**Учебный проект ПК-01**

Консольный прототип для проверки правил онлайн-встречи. Организатор планирует встречу и выдаёт приглашение. Гость подаёт заявку, получает допуск и подключается. После встречи организатор выгружает сведения о присутствии в CSV.

Полный замысел и требования к веб-версии описаны в [техническом задании](docs/TZ_Platforma_dlya_onlain_konferentsiy.docx). Текущий этап работает на классах и коллекциях Python. Данные встреч, сообщений и учётных записей хранятся до закрытия процесса. Выгруженные файлы CSV остаются в каталоге `output/`.

## Запуск

Из корня проекта с Python 3.12 и uv:

```bash
uv sync --locked
uv run python src/main.py
```

Консольный сценарий использует стандартную библиотеку. Его также можно запустить командой `python src/main.py`.

Учебная учётная запись администратора — `admin@example.test`, пароль — `Admin-demo-2026`. Команды `login` и `add-host` запрашивают пароль отдельно. Команда `help` выводит список действий, `exit` закрывает программу.

## Сквозной сценарий

Выполняй команды в одном терминале. Текст в угловых скобках замени значением, которое выдаст программа или которое нужно ввести самостоятельно.

1. Войди как администратор командой `login admin@example.test`. Создай организатора командой `add-host host@example.test` и задай пароль длиной от 12 символов, например `Host-demo-2026`.
2. Войди как организатор командой `login host@example.test`. Создай встречу и запомни её номер и код приглашения.

   ```text
   create "Защита проекта" <дата> 45 "Показ прототипа"
   ```

   Подставь будущее время на 5 минут вперёд с явным смещением. Формат даты — `ГГГГ-ММ-ДДTчч:мм+03:00` или `ГГГГ-ММ-ДДTчч:ммZ`. Начало в пределах ближайших 15 минут позволит сразу проверить запуск и гостевой вход.

3. Для первой встречи выполни `meeting start 1`, затем `guest <код-приглашения> "Иван Иванов"`. Терминал переключится на гостя и выдаст его номер заявки и приватный ключ для возврата.
4. Выполни `login host@example.test`, `queue 1` и `moderate admit 1 1`. За 60 секунд вернись к гостю через `resume <гостевой-ключ>` и введи `join`.
5. Введи `send - "Презентация готова"`, затем `chat -`. Войди как организатор и выдай право выступления командой `moderate speaker-on 1 1`.
6. Снова выбери гостя через `resume <гостевой-ключ>`. Введи `device - mic on`, `device - screen on` и `roster -`. Для проверки переподключения введи `leave`, затем `join` в течение 60 секунд.
7. Войди как организатор, введи `meeting finish 1`, затем `report 1`. Проверь файл `output/attendance_1.csv`.

Переключение между ролями имитирует работу нескольких пользователей. Оно сохраняет гостевое соединение. Команда `leave` отмечает реальное для модели отключение и закрывает текущий интервал присутствия.

## Команды и права

| Роль | Команды |
| --- | --- |
| Все | `help`, `exit`, `login EMAIL`, `logout`, `guest INVITE "Имя"`, `resume KEY` |
| Администратор | `add-host EMAIL`, `block EMAIL on`, `block EMAIL off` |
| Организатор | `create TITLE DATE MINUTES [DESCRIPTION]`, `edit ID TITLE DATE MINUTES [DESCRIPTION]`, `list`, `meeting start ID`, `meeting cancel ID`, `meeting finish ID`, `meeting renew ID`, `queue ID`, `moderate ACTION ID GUEST`, `hide ID MESSAGE`, `report ID` |
| Допущенный гость | `join`, `leave` |
| Организатор и подключённый гость | `roster ID`, `device ID TYPE STATE`, `send ID TEXT`, `chat ID`. В гостевой сессии вместо `ID` используй `-` |

- `moderate` принимает `admit`, `reject`, `kick`, `speaker-on`, `speaker-off`. Номер гостя берётся из очереди.
- Для `device` доступны типы `mic`, `camera`, `screen` и состояния `on`, `off`. У гостя должно быть право выступления.
- Текст с пробелами заключай в двойные кавычки. Квадратные скобки в описании команды обозначают необязательный аргумент.

## Реализованные требования ТЗ

- Владелец создаёт, изменяет, отменяет, запускает и завершает свои встречи. Срок встречи — 15–180 минут. Зал ожидания доступен с 15 минут до начала. При обращении к встрече после её расчётного окончания программа применяет конечный статус.
- Замена приглашения закрывает старый код для новых заявок. Поданные заявки сохраняются. Отзыв допуска завершает соединение гостя.
- В комнате до 20 мест с учётом места организатора, до четырёх выступающих и один активный показ экрана. Просроченный первичный допуск освобождает место и возвращает заявку в очередь.
- Чат доступен во время встречи подключённым пользователям. После переподключения история сохраняется. Организатор может скрыть сообщение.
- CSV доступен владельцу завершённой встречи. В него входят только подтверждённые подключения. При возвращении в пределах 60 секунд отчёт суммирует интервалы одного гостя и исключает паузу между ними.

Микрофон, камера и демонстрация экрана представлены состояниями в Python. Веб-интерфейс, реальные медиапотоки, PostgreSQL и HTTP API относятся к следующим этапам. В прототипе время задаётся смещением UTC, пароль проверяется с помощью `scrypt`, а каждая новая команда создания или отправки считается отдельным действием. Серверная идемпотентность, политика сессий и эксплуатационные сценарии сохраняются в ТЗ как требования будущей версии.

## Структура и проверка

- `src/main.py` — точка входа и сборка компонентов.
- `src/accounts.py` — локальные учётные записи.
- `src/conferences/` — модель и правила комнаты, коллекция встреч и экспорт.
- `src/cli.py` — команды терминала.
- `docs/` — техническое задание и [пояснение архитектуры](docs/ARCHITECTURE.md).
- `tests/` — проверки основных правил и консольного сценария.
- `pyproject.toml` и `uv.lock` — декларация и фиксация зависимостей.

FastAPI, SQLAlchemy, Alembic и Pydantic добавлены через `uv add` для следующих этапов. Ruff и pytest находятся в группе разработки.

```bash
uv run ruff check .
uv run ruff format --check .
uv run pytest
```
