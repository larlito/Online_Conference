# Архитектура консольного прототипа

Точка входа собирает `Accounts`, `Conferences` и `Console`. Консоль переводит текстовые команды в вызовы предметной логики. `Conferences` хранит встречи и выдаёт карточки владельцам и сеансы гостям. Объект `Room` отвечает за переходы состояния одной встречи, гостевые места, права публикации и доступ к чату. Экспорт посещаемости вынесен в отдельный модуль, который читает подтверждённые интервалы.

## Применение SOLID

| Принцип | Решение |
| --- | --- |
| SRP | Разбор терминальных команд, управление учётными записями, правила встречи и запись CSV разнесены по компонентам. |
| OCP | Новый интерфейс может вызывать операции комнаты и учётных записей без изменения их правил. Новый терминальный обработчик регистрируется в таблице команд. |
| LSP | Предметные классы используются через композицию. Иерархии классов с подменяемыми реализациями в этом этапе нет. |
| ISP | Комната предоставляет операции для работы со встречей. Экспорт вынесен отдельно и не добавляет обязанностей консоли или классу учётных записей. |
| DIP | Источник времени передаётся как `Callable[[], datetime]`. Предметная логика не импортирует интерфейс терминала, ORM или среду запуска. |

Осознанное упрощение DIP касается хранилища. `Accounts` и `Conferences` используют словари напрямую. Интерфейс репозитория уместен на этапе подключения постоянного хранилища, когда появятся две реализации. Это решение сохраняет объём учебного прототипа и оставляет правила комнаты независимыми от способа хранения.

Терминал моделирует разных пользователей в одном процессе. Резервы мест и конечное состояние встречи обновляются перед обращением к её данным. Измерение сетевых характеристик, роли веб-приложения и фоновые задачи входят в спецификацию будущей версии.
